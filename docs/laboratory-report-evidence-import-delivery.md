# 检验业务补齐交付说明（2026-10-11）

本轮补齐设备项目能力、批次/上机/消耗证据桥接、报告业务签发与私有 PDF、九类 Excel 导入。代码、迁移、前端及测试已实现；没有部署到现有 `ivd` 数据库，没有替换 8080/5173 服务，没有提交或推送本轮改动。此交付不等于全系统机构隔离已通过上线验收。

## 设备与项目能力

- 复用库存模块既有 `device` 表和设备 ID，不另建设备表。设备档案支持编码、名称、型号、厂家、库房、科室、启停和校准日期；库房层级、科室归属、启用状态及版本由服务端校验。
- 专用注册 Service 使用条件版本写入，避免新增版本列影响尚未迁移的旧设备 Mapper 查询。部门目录通过共享 Service port 验证，没有引入 inventory→system 反向依赖或外部 Mapper。
- `lab_test_item.device_required` 决定是否允许手工检测；外送仍须选择本院维护的外送机构，不绑定本地设备。仪器结果必须引用明确启用的 `lab_device_capability`，不能从参考区间推断设备能力。
- 录入期间按项目→设备→能力行锁顺序校验，配置停用不能与新结果写入交错。历史结果保存原有依据，不因配置停用重写。
- 前端 `/lab/devices` 提供档案与可执行项目；项目编辑增加“要求仪器”。

## 真实业务证据桥接

`患者 → 样本 → 结果版本 → lab_result_evidence → 原 reagent_batch / device_batch_load / consumption_record`

- 跨模块只调用库存/消耗 Service。引用真实 ID、机构及科室可见性；校验试剂一致、设备一致、上机时间段、正向消耗和正数量。
- 历史记录只有批号、没有可靠 batch ID 时不自动匹配。批次、上机和消耗下拉源来自后端真实数据，各最多100条，支持批号搜索。
- 证据与结果版本绑定，保存加密快照、关联人和时间，数据库触发器拒绝 UPDATE/DELETE；同一绑定请求幂等。
- 错误证据不覆盖：修订结果产生新版本，再关联新证据。待复核/已复核报告引用的结果禁止修改或追加证据，先由有权人员退回。
- `/lab/evidence` 支持按实际批次 ID/消耗 ID 反查有权访问的患者、样本和所关联的历史结果版本，不误用较新的结果修订。
- 此操作不扣库存，不生成消耗或结算；不存在将新患者 HMAC 自动等同于旧 `patient_association.patient_id_hash` 的逻辑。旧匿名患者关联仍保持“未确认”，不自动合并或泄露。

## 报告闭环与版本

正常流程：`DRAFT → PENDING_REVIEW → REVIEWED → SIGNED`。

- 草稿/退回状态可编辑；提交时重新捕获当前结果、患者、区间和证据快照。已签发报告不会随基础资料或结果修订变化。
- 报告创建、编辑、提交、更正、结果录入/修订和证据关联人员均计入录入人员，不能复核或签发自己参与录入的报告。其他授权临床人员复核，主任角色签发；复核人与签发人可相同。
- 异常、缺失、单位问题或证据不完整必须人工确认风险并填写说明；不生成诊断，不自动复核或签发。
- 可退回重编；更正创建新报告版次，重新复核签发，成功后原版标记 `SUPERSEDED`；撤销需原因，保留原版和不可变事件。撤销/被替代版本禁止正常业务打印下载。
- 并发签发持有报告/家族锁；同一签发人的重复确认返回同一摘要和版本，不新增对象。不同签发人不能重复签发。
- 前端从样本建立报告，`/lab/reports` 查看流转、人工复核、业务签发、更正撤销、报告版本及事件留痕。

## 中文 PDF、私有存储和 CA 边界

- 使用 Apache PDFBox 3.0.8，随应用加载 OFL 字体；中文、多页、列内换行、项目说明、重复报告编号、页码与业务签发提示均有渲染检查。没有 Windows 字体绝对路径；字体不支持的字符拒绝签发，不静默替换患者资料。
- 时间显示为本地毫秒精度，范围采用等值精简显示；数据库和加密快照保留原值。PDF 生成最多四个并发请求，繁忙时拒绝且不改变签发状态。
- PDF 字节以独立临床密钥 AES-GCM 加密后存入 MinIO 私有桶，技术对象路径不包含患者姓名/编号。存储拒绝公共策略，不暴露预签名 URL；通过后端机构、科室及患者授权获取，解密并验证 SHA-256 摘要。
- 存储失败不进入 SIGNED。数据库事务回滚会尝试删除该次新对象；清理失败只记录技术报告 ID，需管理员核对对应孤立对象，不宣称回滚清理永远成功。
- `GET /api/v1/lab/reports/{id}/pdf?purpose=PREVIEW|DOWNLOAD|PRINT` 全部鉴权并审计，响应禁止缓存。未签发仅允许带草稿提示的预览；前端提供受控打印阅览和下载。
- 已合法取得的 PDF 副本及浏览器原生保存/打印无法远程收回；撤销阻止后续受控获取，不能承诺撤销已有纸质或离线副本。
- 首版只有业务签发，界面和每页 PDF 明确“未使用 CA 数字签名”。预留 `CaSignatureService` 签名、验签、证书信息接口；未配置实现显式不可用，绝不模拟验签成功。真实 CA 厂商接入仍是后续阶段。

## 九类 Excel 预检与执行

资源：`PATIENTS / SAMPLES / RESULTS / REPORTS / ITEMS / INTERVALS / DEVICES / CAPABILITIES / INSTITUTIONS`。

- `/lab/imports` 下载空模板、选择工作簿、预检、人工确认、查看行级错误和执行回执；普通临床用户不能导入管理资料，管理员不默认获得患者/报告导入权。
- 只接受单表、无宏/外部链接的 `.xlsx`，10MB、5000行，解压总量64MB；拒绝公式、错误单元格、未知/重复表头、合并表头及重复业务键。真实表头映射，允许列重排。
- 编码/ID/手机号等文本列必须是文本，保留前导零；日期时间使用本地 ISO，布尔值 TRUE/FALSE 或1/0，枚举使用原代码。结果导入单位必须与项目一致，不自动换算。
- 预检通过真实业务 Service 在回滚事务中验证，不留患者、结果、报告或成功审计；预检可能分配后回滚 AUTO_INCREMENT 技术 ID，因此出现序号空隙是正常的，不改变已有 ID。
- 默认仅新增，不覆盖已存在资料、结果或签发报告。样本导入为已采集，不自动接收；结果引用已接收样本。报告工作簿按报告编号分组，同份报告及所有结果一个事务，任一行失败整组回滚，只生成草稿。
- 基础资料/单结果按行事务。每个成功业务单元与不可变回执同一事务提交；重复确认不重复写入。执行中断时使用执行租约和回执恢复未完成单元，不因主批次最终状态尚未提交而重复导入。
- 预检24小时有效；执行租约15分钟，由各单元更新。客户端可刷新回执；需要长期大批量作业时应控制并发和应用资源，不能把本轮少量用例联调当作5000行性能基准。
- 导入文档、结果和错误持久化均加密，错误不回显患者原始值；不存原文件名到业务日志，不将患者资料保存到浏览器存储。部署的 Servlet 临时上传目录仍应限制到应用账户并按请求清理。
