# 患者档案后端实现与启用边界

此文档记录患者后端切片。后续已补充患者前端、样本及草稿结果关联，见 [最新样本与结果说明](laboratory-sample-result-implementation.md)；仍不代表报告签发、Excel 导入或 PDF 已完成，现有 `ivd` 业务库未迁移。

## 已实现

- 最小人口学资料：机构内患者编号、姓名、性别、可空出生日期。不默认采集证件、联系方式、诊断或处方。
- AES-GCM 加密保存完整资料；患者编号以机构绑定 HMAC 唯一索引匹配，不另存明文姓名、编号或出生日期。
- 解密后校验患者编号 HMAC 与记录索引一致，拒绝单独替换密文导致的患者错配；这不是对数据库管理员整体篡改所有元数据的防护。临床 Mapper 禁止参数级 DEBUG 日志，避免复制密文到应用日志。
- 检验人员/医生/主任仅能读写明确授权科室的档案；默认仅创建科室获得授权。系统管理员不能列出、读取或修改患者明文详情。
- 系统管理员仅能使用患者 ID 显式授权/撤销本机构科室，并记录用途代码；此操作只读取患者 ID，不解密人口学资料。用途不得填写患者信息自由文本。
- 列表只返回脱敏姓名/编号及技术 ID/版本，不返回出生日期。敏感详情与所有操作显式持久化审计；审计缺失或临床密钥缺失时失败，不返回敏感结果。
- 更新必须携带版本；修改时锁定科室授权，拒绝过期覆盖。不自动合并跨科室资料，不自动共享同编号患者。
- 请求格式错误和未知临床异常使用独立脱敏异常处理，不返回原始解析消息或患者输入。

## API

| 方法 | URL | 权限 |
|---|---|---|
| GET / POST | `/api/v1/lab/patients` | 授权科室临床用户：脱敏分页 / 新建 |
| GET / PUT | `/api/v1/lab/patients/{id}` | 授权科室临床用户：详情 / 版本更新 |
| POST | `/api/v1/lab/patients/{id}/departments` | 系统管理员：本机构科室授权/撤销 |

授权用途 `CLINICAL_COLLABORATION / CORRECTION` 用于启用，`REVOCATION` 用于撤销。既有业务返回格式和错误码保持一致，跨机构/科室详情均返回不存在或无权访问。

## 部署条件

新增 `V20261010007__encrypted_patients_and_department_access.sql`，包含患者、科室授权及复合归属外键，无患者种子数据，不修改已执行迁移。

启用必须同时满足：全系统机构隔离验收通过、暂停写入并备份后完成迁移、`IVD_ISOLATION_ENABLED=true`、`IVD_CLINICAL_ENABLED=true`、通过安全配置提供 `IVD_CLINICAL_ENCRYPTION_KEY`（独立随机32字节的 Base64，不得复用 JWT）。没有默认临床密钥，缺失时在 Flyway 执行前拒绝启动；临床表结构缺失亦拒绝启用。

严禁把测试用零字节密钥作为部署密钥。密钥轮换需另行制定历史密文重加密及 HMAC 重索引方案，不可直接换环境变量导致历史资料不可读。实际密钥、患者资料和备份不得提交 Git。

`features.labPatients` 仅表示后端 API 能力已显式启用，不代表患者前端、报告或导入功能已实现。
