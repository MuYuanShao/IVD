# 商品目录变更闭环修复

## 行为

- 编辑保存到独立 `catalog_draft`；正式目录字段及五码映射在审批通过后才应用。
- 编辑后状态为 DRAFT，提交后为 PENDING。待审批草稿不可再次编辑；驳回后可重新编辑提交。
- 每次有效新增、编辑、删除都在同一事务追加 `catalog_change_log`，保存字段前后值、服务端操作人、时间及当时的名称/编码。
- 审批提交保留完整快照；序列化失败回滚，不再用空对象冒充成功。审批校验提交版本并加锁，损坏的旧审批须驳回后重新提交。
- 清空开瓶稳定天数、可选单价保存为 NULL；清空采购提前期恢复默认7天。未提交的字段不变；试剂测试数不可清空。
- 目录行“变更记录”进入已筛选的信息变更页面，“变更详情”显示旧值/新值。旧审批记录保留；未曾保存的历史旧值无法追补，不伪造。
- 合并历史从各来源获取所需排序前缀，再统一分页，使用稳定排序；含结束日期当天。组合查询超过10,000条前缀须增加日期/模块筛选。

## 部署注意

新增迁移 `V20261011005__catalog_drafts_and_change_history.sql`，含草稿表、机构归属及两个禁止 UPDATE/DELETE 的历史表触发器。不修改已执行迁移。

本轮不自动修改业务数据库，不替换运行中的前后端。部署前暂停写入、备份、核对 Flyway 历史及机构隔离开关，再按既有迁移流程执行新增脚本并重新登录。请勿跳过未完成的机构归属迁移或关闭 checksum 校验；新 JAR 依赖新增表。

新版本启动时检查草稿/历史表及 MySQL 不可变保护触发器；缺失即拒绝启动，避免先修改目录后才发现没有历史记录。

已存在的普通编辑没有字段差异记录，不能从当前目录恢复真实旧值。旧空审批快照也不能恢复，必须重新提交有效审批。
