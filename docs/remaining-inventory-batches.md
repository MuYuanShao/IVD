# 在库批次独立功能

入口：三级库存 → 在库批次列表，路由 `/inventory/remaining-batches`。首页正式工作台不再展示该表格或调用原工作台商品分页接口；演示页面保留演示商品列表。

接口：`GET /api/v1/inventory/remaining-batches`，支持 `page`、`pageSize`（1～100）、`keyword`（最长100字符）、`level`（1～3）；返回统一分页VO，批次ID为字符串，数量和价格保留十进制精度。只读，不允许直接编辑派生库存。

新增迁移：`V20261011007__remaining_inventory_batch_projection.sql`。MySQL表 `inventory_remaining_batch` 以原库存批次为来源，保存机构、批次ID、剩余数量、来源版本及创建/同步时间。一库存批次对应一行，名称、厂家、规格及库位按机构联接当前目录、批次与库房信息，避免复制主数据后过时。数量大于零即纳入，过期或召回批次仍保留状态，不能把在库误认为可用库存。

迁移初次从 `reagent_batch.stock>0` 填充；两个数据库触发器随来源INSERT/UPDATE同事务同步，数量归零移除，重新有余量时恢复；来源删除通过外键级联删除。触发器失败时来源库存事务也失败，不异步静默丢失。原库存、金额、结算及历史流水不被改写。不得将此表作为扣库来源或手工调整该表。

机构由服务端上下文限定；机构管理员、库管、财务查看机构范围，临床及科室用户查看中心库和本人科室/下属组库，缺少科室归属拒绝访问。列表不提供跨机构参数。

已用独立虚构MySQL库验证填充、插入、更新、小数数量、回滚、清零、补货恢复与删除联动；真实Mapper集成测试验证分页、机构及科室边界。前端遵循现有Element Plus样式，保留搜索、分页、加载、空态、错误提示及取消过时请求。

上线需先备份暂停写入，以正常Flyway校验执行007后再替换前后端；数据库迁移账号需具备TRIGGER权限。不得修改旧迁移、关闭校验或在未安装007的正式库上启动新功能。
