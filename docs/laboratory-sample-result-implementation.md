本切片实现手工临床关联，不代表完整报告、导入或全系统隔离已交付。现有业务库及 8080/5173 服务不部署本切片。

后续 2026-10-11 已补齐设备能力、证据桥接、报告/PDF和导入，当前状态见 [最新交付说明](laboratory-report-evidence-import-delivery.md)；本文“未交付范围”保留为前一切片历史记录，不表示这些新功能仍为占位。

## 已实现关系

`lab_patient → lab_sample → lab_result → device / lab_test_item / 实际检测机构`

- 一个患者可有多个样本；同一样本可有多个检验项目。首版同一样本、同一项目只有一份当前草稿结果，重复新增返回冲突；使用版本修订，不静默覆盖。复测独立订单/多次检测建模尚未交付。
- 样本编号手工填写，机构内唯一；不自行生成新业务单号。样本归属机构、科室和操作人全部由服务端确认。
- 样本状态 `COLLECTED → RECEIVED / REJECTED`，拒收必须说明原因，终态不可再次接收或拒收；接收后才能录入结果。状态更新、不可变事件及成功审计在同一事务提交。
- 仪器检测必须选择本机构、本科室有权访问且启用的实际设备；手工检测不绑定设备；外送检测只引用本院维护的外送机构，不绑定本地设备，也不赋予外送机构临床访问权。
- 当前检测方式由录入人明确选择。项目级“必须使用仪器”能力配置和设备可执行项目清单仍需另行实现，不把区间关联当作设备能力认证。
- 患者科室授权不会自动开放其他科室的样本或结果；撤销患者授权后样本及结果也不可读写。写操作在业务事务内锁定有效患者授权，避免授权撤销和结果写入交错。
- 年龄和性别来自授权患者档案，按采集日期计算年龄；方法学来自检验项目。请求不能自行填写这些判定依据。缺少出生日期、区间缺失/冲突、单位不一致均保留人工处理提示，不判为正常、不换算单位、不生成诊断。
- 检测结果与患者、样本、项目、设备、检测机构及匹配区间的依据快照一起加密保存；后续修改基础资料不会重写既有快照。修订产生新版本，旧版本仍可鉴权查看。所有结果均为草稿，不可当作正式签发报告。
- 支持患者→样本→设备、设备→结果→样本→患者 ID 查询。关联查询同样受机构、科室及当前患者授权限制，不支持系统管理员默认读取临床详情。

## 新接口及页面

| 方法 | 资源 | 功能 |
|---|---|---|
| GET / POST | `/api/v1/lab/samples` | 脱敏分页 / 登记样本；列表可按 `patientId` 筛选 |
| GET | `/api/v1/lab/samples/{id}` | 授权样本详情 |
| POST | `/api/v1/lab/samples/{id}/receive`、`reject` | 携带 `version` 接收或拒收 |
| GET / POST | `/api/v1/lab/samples/{id}/results` | 结果分页 / 新建草稿 |
| GET / PUT | `/api/v1/lab/results/{id}` | 详情 / 携带版本修订 |
| GET | `/api/v1/lab/results/{id}/versions` | 历史结果及区间快照 |
| GET | `/api/v1/lab/results` | 按 `patientId` / `deviceId` 查询授权关联 |
| GET | `/api/v1/lab/testing-institutions/options` | 本院及本院维护的启用外送机构 |

前端新增 `/lab/patients`、`/lab/samples`、`/lab/results`。患者列表脱敏，进入详情留痕；从患者行登记样本，进入样本详情接收/拒收及录入结果。设备关联查询支持按设备搜索。页面、Modal、Panel 分离，复用现有 Element Plus 主题。API 统一走 `src/api/clinical.js`，不存储患者资料到 localStorage/sessionStorage。

临床新接口时间使用本地 ISO `yyyy-MM-dd'T'HH:mm:ss.SSS`，不带时区，不改变旧业务时间格式；客户端录入必须以部署机构本地时间为准。临床密文文档使用独立对称 ISO 时间 codec，避免应用既有“空格序列化 / ISO反序列化”设置破坏快照读取。

## 迁移与安全边界

- 新增 `V20261010008__samples_and_result_evidence.sql`：样本、样本事件、结果及结果历史四张表，机构复合外键、机构内唯一索引、状态/设备约束；新增四个事件/历史防 UPDATE/DELETE 触发器。不修改已执行迁移，不移除旧触发器。
- 临床启动保护要求患者、授权、样本、事件、结果、历史表全部存在，并配置独立随机临床密钥和机构隔离开关；缺少条件拒绝启用。
- 样本编号/类型/采集信息、拒收说明、结果/临床快照加密保存；列表只暴露脱敏编号和技术 ID；请求解析错误脱敏。临床 Mapper 不开启参数级 DEBUG。读取及修改审计，不将人口学资料写入审计原因。
- 结果修订使用乐观版本校验和数据库锁；仪器→手工/外送修订会真实置空原设备外键，不能依赖 ORM 默认非空更新策略。
- 不部署到 `ivd`：必须先完成全系统机构隔离验收，暂停写入、备份、正常 Flyway 校验和数量/金额/关联核对，再按维护窗口上线并重新登录。此文档不是生产隔离上线批准。
